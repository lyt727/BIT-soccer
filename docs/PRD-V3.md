## 1. 目标

**现状痛点**

- 报名散在群聊和表格里：谁报没报、材料齐不齐，靠人工催、易漏。
- 分组、赛程、积分榜、射手榜分开维护：抽签、排赛程、改数据全靠人工，数据不统一、错误难追溯。
- 录分靠手工：进球、换人、红黄牌从裁判纸上逐项敲，一场 20 分钟，榜单滞后数天。
- 各部门工作人员统计表分散：发补贴时难汇总。

**目标**：把"录比赛结果"变成唯一的人工环节，其余由系统自动完成。

| 指标 | 口径 | 目标 |
|---|---|---|
| 报名审核耗时 | 提交 → 审核完成 | ≤ 1 个工作日 |
| 榜单准确率 | 与已录入结果一致 | 100%（系统计算） |
| AI 识图有效率 | 识别后人工直接采用的比例 | ≥ 80% |
| 单场录分耗时 | 结果录入 → 榜单更新 | 人工 < 5 分钟；AI 识图 + 复核 < 2 分钟 |

V3 已用真实裁判报告照片跑通识别链路（Qwen-VL-Max）；识别不全时一律留空或转人工，绝不写入脏数据。

## 2. 用户与权限

**系统角色（权限为包含关系：参赛球员 ⊆ 数据录入员 ⊆ 管理员）**

| 角色 | 是谁 | 核心权限 |
|---|---|---|
| 管理员 | 校足协 | 建/删赛事、切换状态、审核报名、抽签、排赛程、指派工作人员、修订结果、认证成员角色、查看日志 |
| 数据录入员 | 被指派的同学 | 在被指派赛事内：录结果、AI 识图、编辑比赛信息、填写特殊情况与比赛工作人员 |
| 参赛球员 | 各队成员 | 报名/加入球队、完善本人信息、查看赛程与榜单 |

> 队内角色（主教练 / 领队 / 队长 / 队员）是球队内部分工，不等于系统角色。

**两级授权**：全局角色决定"能做哪类事"，赛事指派（`event_staff`）决定"能管哪届赛事"；关键写操作全部记录审计日志，云数据库用 RLS 兜底。

**能力矩阵**

| 能力 | 管理员 | 数据录入员 | 参赛球员 |
|---|---|---|---|
| 查看赛事 / 赛程 / 榜单 | ✅ | ✅ | ✅ |
| 建删赛事、切换状态、编辑赛事信息 | ✅ | — | — |
| 审核报名、查看完整报名信息 | ✅ | ✅（只读） | ✅（只读） |
| 抽签编排（分组 / 单循环对阵 / 淘汰赛对手）| ✅ | — | — |
| 添加比赛（仅赛事"进行中"时）| ✅ | ✅（仅淘汰赛，被指派赛事）| — |
| 编辑 / 删除比赛信息 | ✅ | ✅（进行中，被指派赛事；赛事已结束后锁定，仅管理员可更正）| — |
| 录结果、AI 识图、AI 生成战报、特殊情况、比赛工作人员 | ✅ | ✅（被指派赛事） | 战报只读 |
| 报名 / 加入球队 / 取消报名 | ✅ | ✅ | ✅ |
| 操作日志、成员角色认证 | ✅ | — | — |

## 3. 核心流程

`建赛事（选赛制）→ 报名 / 加入球队 → 审核 → 报名截止 → 抽签编排 → 排比赛 → 录结果（AI 识图 / 人工）→ 榜单与工作统计自动更新 → 生成战报 → 导出`

**赛事状态**：待开始 / 报名中 / 进行中 / 已结束，四种状态用不同颜色区分。管理员可任意切换（非单项流转）；报名中可编辑名单，切到进行中后报名与名单锁定（`REG_LOCKED`）。

**状态与操作的对应关系**（三种赛制一致）：

| 操作 | 待开始 | 报名中 | 进行中 | 已结束 |
|---|---|---|---|---|
| 报名 / 审核 / 修改名单 | — | ✅ | ❌ 已锁定 | ❌ |
| 抽签编排（分组或对阵）| ❌ | ❌ | ✅ | ❌ |
| 添加比赛 | ❌ | ❌ | ✅ | ❌ |
| 编辑单场比赛信息 | — | — | ✅ | ✅（仅管理员）|
| AI 识图 / 编辑数据 | — | — | ✅ | ❌ 已锁定 |
| 编辑赛事名称与介绍 | ✅ | ✅ | ✅ | ✅ |

抽签与添加比赛**互不依赖**，管理员可任意先后；两者都要求在报名结束（赛事"进行中"）之后。

**当前使用规模**：15 支球队、A/B/C/D 四组（4/4/4/3）、每队 15 人；21 场小组赛 + 淘汰赛。

## 4. 功能需求

### 4.1 账号与登录
- **手机号 + 姓名 + 密码**登录注册，新账号默认角色为参赛球员；密码用 scrypt 加盐散列存储，任何接口都不返回散列。
- 账号不存在与密码错误返回同一句提示，避免暴露手机号是否已注册；登录失败写审计日志（含来源 IP）。
- **角色按手机号认证**：管理员可在"成员"页把某个手机号升级为管理员或数据录入员，也可停用账号、重置密码。
- 短信验证码登录作为备选通道保留：配置腾讯云 / 阿里云短信后可用，服务端限频（60 秒/次、5 次校验、5 分钟过期）。

### 4.2 赛事管理
- 首页展示进行中赛事横幅 + 全部赛事卡片（球队数、已完成/总场次、小组数、状态）。
- 管理员可创建赛事、编辑赛事名称与介绍、删除赛事（二次确认，级联删除报名/分组/赛程/统计）。
- 赛事状态四种，管理员可任意切换；不同状态用不同颜色标识，非管理员只读。

### 4.3 球队报名
- 任意角色都可以**创建球队**或**加入已有球队**（含管理员、数据录入员）；同一人在同一赛事只能报一支队（互斥），可随时取消本人报名。
- 每队必须上报：**球衣上衣、短裤、球袜三种颜色**；每名成员上报姓名、手机号、学生卡照片、队内角色、球衣号码。
- 队内角色：主教练 / 领队 / 队长 / 队员，可一人多职；**每队只能有一名主教练、一名队长**。
- 队长与队员必须有球衣号码，**同队号码不能重复**；号码不要求连续，名单按号码升序排列。
- 报名期间可编辑整队名单或完善本人信息；赛事进入"进行中"后服务端锁定（`REG_LOCKED`）。
- 报名列表展示每队球衣三色、主教练、队长；点"详细名单"查看全员号码、手机号和学生卡（学生卡点按查看，仅管理员可见完整信息）。
- 管理员拥有审核权限：通过 / 拒绝（可填原因）；未审核的球队也照常显示，便于报名截止后统一审核。
- 名单排序：主教练 → 领队 → 参赛队员（号码升序），列表最前面的圆形序号即球衣号码。

### 4.4 抽签编排
**只有审核通过的球队参与抽签**；仅赛事状态为"进行中"（报名已结束）时可执行。三种赛制的抽签规则不同：

| 赛制 | 抽签做什么 |
|---|---|
| 小组赛 + 淘汰赛 | 随机均衡分组，组数可选 2/3/4/6，组间球队数差 ≤ 1 |
| 单循环联赛 | 按轮转法生成全部对阵（每两队交手一次）并平均分配到各轮 |
| 纯淘汰赛 | 随机配对决定首轮对手；球队数为奇数时最后一支轮空；首轮轮次按队数自动推断（1/8 决赛 → 决赛），可手动改 |

抽签不是必须的：三种赛制都可以不抽签，由管理员手动逐场添加。重新抽签覆盖旧结果，界面提前提示；**已录入比赛结果后禁止重新抽签**，避免成绩丢失。

### 4.5 赛程安排
- **赛制三选一**（创建赛事时选定，已有赛程后不可修改）：
  - **单循环联赛**：每两队交手一次，抽签时按轮转法生成全部对阵并分配到各轮；积分榜为一张总表。
  - **小组赛 + 淘汰赛**：小组赛（A–F 组）+ 单回合淘汰赛。
  - **纯淘汰赛**：对阵全部手动添加，不产生积分榜。
- **淘汰赛轮次**：1/8 决赛、1/4 决赛、半决赛、三四名决赛、决赛，也可自定义名称（≤ 20 字）。
- 每场比赛后面提供入口：**技术统计与时间轴**、**AI 识图**、**AI 生成战报**、**特殊情况说明**（特殊情况仅管理员与数据录入员可编辑，参赛球员只读）。
- **必填项只有：比赛阶段、轮次、主客队**；日期、时间、场地、裁判组、名单、球衣颜色、备注均为选填。
- 裁判组固定四人：主裁判、第一助理、第二助理、第四官员。
- 每队的上场人数（首发上限 3–11 人，对应十一人制 / 七人制 / 五人制）由管理员在赛事里设置，替补人数不限。

### 4.6 比赛技术统计与时间轴
每场比赛详情包含：

- **双方首发 / 替补名单**：从该队报名名单点选，只显示号码与姓名（不另加序号）；临场标注队长 © 与守门员 🧤（图标在号码左侧，队长在守门员左边）；状态可选 `－ / 首发 / 替补`；首发非空时必须有且只有 1 名队长和 1 名守门员。
- **比赛服颜色**：上衣、短裤、球袜。
- **竖版时间轴**：进球、换人、红黄牌，逐条记录球员 / 号码与时间。
- **裁判组**：四人。
- **比赛工作人员**：比赛监督、拍照、录像、解说、战报（各自手动填姓名）。
- 技术统计与时间轴页面**只做展示**，修改统一走"编辑比赛信息"或 AI 识图。

### 4.7 结果录入
- 每场比赛的"编辑"进入**统一数据编辑界面**：比赛信息 + 技术数据 + 工作人员，一页改完。
- 录入内容：比分、进球（球员 / 号码 / 时间 / 是否点球）、换人、红黄牌、裁判组、首发替补、球衣颜色、特殊情况、工作人员。
- 进球名单行数必须与比分一致，每球一行，允许留空记为"未登记"。
- 提交后自动重算积分榜、射手榜；编辑时页面保持在原位，不跳动、不回到顶部。
- 权限：赛事"进行中"时管理员与被指派的数据录入员可编辑；赛事"已结束"后仅管理员可更正，录入员与参赛球员只读。

### 4.8 AI 识图：裁判报告 → 结构化数据
- **入口**：赛程安排里每场比赛的"AI 识图"按钮，与技术统计、AI 生成战报并列。
- **上传**：JPG / PNG，**一次最多 3 张**（裁判报告一般两页 A4），单张 ≤ 12MB，前端压缩到 1600px 后上传。
- **一次识别输出的内容**：双方首发与替补（号码 + 姓名）、比赛服三色、比分、进球（含点球）、换人（换上 / 换下 + 时间）、红黄牌（球员 + 时间）、裁判组。
- **识别范围严格限定在裁判报告内**：日期、开球时间、场地、工作人员、特殊情况不在裁判报告上，不识别、不猜测。
- **禁止编造**：提示词要求逐项对应报告文字，报告上没有的信息一律留空，不得凭常识补全。
- **白名单校验**：识别出的球员与该队报名名单比对——号码或姓名命中才自动采用；形近字等模糊相似只给候选提示，不自动替换，避免改错人。
- 识别结果逐项可人工修正；复核后一键填入并提交，榜单自动更新。
- **失败兜底**：识别失败、返回为空或校验不通过时，明确提示"请改用人工录入"，直接跳到统一数据编辑界面，**不写入任何脏数据**。
- 每次识别写审计日志；模型为 Qwen-VL-Max（阿里云百炼 OpenAI 兼容模式），Key 与模型名都在 `.env`，可整体换厂商。

### 4.9 AI 生成战报
- **入口**：赛程安排里每场比赛的"AI 生成战报"按钮；生成过之后按钮变为"查看 AI 战报"。
- **前置条件**：仅已完赛的比赛可生成；未完赛点击时弹窗提示"比赛尚未结束，无法生成战报"。
- **数据来源**：全部取自系统内已有结构化数据（比分、进球、换人、红黄牌、双方名单、裁判组、赛事阶段），不依赖图片。
- **硬性约束**：只准使用给定数据、不得添加数据里没有的信息；不得编造场面描写；**禁止出现"主队""客队"以及"主场""客场""坐镇主场""客战"等说法，一律直接写球队名称**；队名、场地、赛事名遵循数据里的写法；不得写"提前出线""首胜"这类需要其他比赛结果才能判断的结论。
- **篇幅与风格**：200–300 字，用足球赛事的常用说法，连接词自然，分 2–3 段，不用小标题、不用 Markdown、不用表情符号。
- **生成后**：正文可人工编辑、可复制；每场比赛**只允许重新生成一次**，之后只能手工修改。
- **权限**：管理员与数据录入员可生成、编辑；参赛球员只读。
- **模型**：Qwen-Plus（与识图共用同一套百炼 Key，改 `.env` 即可换模型）；模型不可用时自动退回本地模板生成，保证一定有正文。
- 代码层兜底：万一模型仍写出"主队 / 客队 / 主场 / 客场"字样，服务端会机械清洗为真实队名或直接删掉。

### 4.10 数据统计
内容随赛制变化：

| 赛制 | 积分榜 | 其余榜单 |
|---|---|---|
| 小组赛 + 淘汰赛 | 按 A/B/C/D 组分别排名 | 射手榜、红牌记录、黄牌记录 |
| 单循环联赛 | 一张联赛总表 | 同上 |
| 纯淘汰赛 | 无积分榜 | 同上 |

- 积分规则：胜 3 平 1 负 0，同分依次比较净胜球、进球数。
- **射手榜**：全赛事汇总，按进球数降序，同进球数点球少者列前；末列为"点球"（右对齐）。
- 排行类榜单按 **球队 → 球员 → 号码** 排序。
- 淘汰赛赛果在赛程安排里查看，不重复放在数据统计页。

### 4.11 红黄牌记录与停赛名单
**红牌记录**：球队 / 球员 / 号码 / 红牌数 / 停赛场次 / 状态 / 备注（红牌停赛至少一轮）
**黄牌记录**：球队 / 球员 / 号码 / 总黄牌数 / 累计黄牌数 / 状态 / 备注（累计 X 张黄牌停赛一场，X 由管理员设定）

- 红牌数、总黄牌数由比赛数据自动统计，整届赛事累加；累计黄牌数 = 总黄牌数 − 已执行停赛写入的清零值。
- **状态由管理员在榜上直接下拉选择**：红牌二选一（下一轮停赛 / 已执行停赛）；黄牌三选一（`-` / 下一轮停赛 / 已执行停赛）。
- **停赛场次**由管理员手动选择（1–10 场）。
- **备注（选填）**：如"辱骂裁判，停赛 5 场"，与停赛名单显示的是同一条记录，任一处修改两处同步。
- **停赛名单**：独立台账，管理员可登记任意原因的停赛（红牌 / 累计黄牌 / 其他原因）、标记已执行（同时清零累计黄牌）、标记失效、删除。
- 录入比赛结果时若有人被罚下，系统自动登记一条"下一轮停赛"，保证红牌状态不空。
- 在榜单里编辑数据后页面保持原位，不跳到顶部。

### 4.12 工作统计
- 裁判组统计：主裁判、第一助理、第二助理、第四官员；
- 其他工作人员统计：比赛监督、拍照、录像、解说、战报；
- 每张表包含角色、姓名、工作场次，按场次从多到少排序。

### 4.13 导出到 Excel
- **赛程安排**：一次性导出该赛事全部比赛，含两支球队名称、比分、比赛阶段、组别、淘汰赛轮次等；
- **数据统计**：积分榜（分组合计或联赛总表）、射手榜、红牌记录、黄牌记录分别导出；
- **工作统计**：裁判组、其他工作人员分别导出；
- 导出格式 `.xls`，Excel / WPS 可直接打开；手机端优先调用系统分享。

## 5. 数据模型（核心）

| 实体 | 关键字段 |
|---|---|
| users | phone、name、role、status |
| events | name、season、description、status、format（赛制）、players_per_side（每队上场人数）、yellow_suspension_threshold（累计黄牌门槛）|
| event_staff | event_id、user_id、event_role（赛事级授权） |
| registrations | team_name、球衣三色、status、created_by |
| registration_members | name、phone、roles、jersey_no、is_contact |
| files | 学生卡照片（文件级权限） |
| event_groups | 小组与球队 |
| matches | 阶段、组别、淘汰赛轮次、轮次名、主客队、比分、裁判组、工作人员、特殊情况、名单、report（战报）、report_regen_count |
| match_goals / match_subs / match_cards | 进球、换人、红黄牌明细 |
| player_suspensions | 停赛台账：球员、原因（红牌 / 累计黄牌 / 其他）、停赛场次、状态、清零值、备注 |
| audit_log | 关键操作留痕 |

积分榜、射手榜为派生数据，实时计算，不单独存储，保证与比赛结果一致。任何数据改动立即生效于所有角色视图（管理员、数据录入员、参赛球员看到的数据始终一致）。

## 6. 非功能要求

| 项 | 要求 |
|---|---|
| 多端 | 手机浏览器优先（PWA 可直接使用），安卓 / iOS / 鸿蒙实测可用；桌面可用；标签栏窄屏可左右滑动、列表项窄屏上下布局、横向表格可滑动 |
| 权限与安全 | RBAC + 赛事级指派 + 文件级校验 + 审计日志；生产可加 RLS |
| 数据一致性 | 榜单 / 统计实时重算；名单在服务端锁定；任一改动立即对所有角色生效 |
| 上传限制 | 仅 JPG/PNG，单张 ≤ 12MB，AI 识图一次最多 3 张 |
| 密码安全 | scrypt 加盐散列；接口不回传散列；重置密码立即失效旧密码 |
| 验证码安全 | 60 秒限频、5 次校验上限、5 分钟过期；演示验证码生产环境默认关闭 |
| 部署 | Docker Compose 一键部署；Caddy 自动申请并续期 HTTPS 证书；可接云数据库 |

## 9. 验收标准

- **管理员**：建赛事（选赛制、设每队上场人数）→ 审核报名 → 切到"进行中" → 抽签编排（或直接手动排赛）→ 录结果 / AI 识图 → 指派录入员 → 认证成员角色 → 查看榜单与工作统计 → 生成战报 → 导出 Excel。
- **参赛球员**：注册 → 创建 / 加入球队 → 上报球衣三色与本人信息 → 取消报名 → 查看赛程、榜单与战报（只读）。
- **数据录入员**：添加淘汰赛并选择轮次 → 编辑比赛信息（统一界面）→ AI 识图复核落库 → 名单点选首发替补 → 填写特殊情况与工作人员 → 维护红黄牌与停赛名单 → 生成战报。

  - `node scripts/test-report.mjs` AI 战报（30 项）
  - `node scripts/test-lineup.mjs` 名单 / 队长 / 守门员 / 人数上限（25 项）
  - `node scripts/test-match-editor.mjs` 统一编辑界面（24 项）
  - `node scripts/test-role-sync.mjs` 按手机号认证角色（15 项）
