# 绿茵BIT · 云数据库方案

## 1. 选型

| 项 | 方案 | 说明 |
|---|---|---|
| 本地演示 | SQLite（Node 内置 `node:sqlite`）| 零依赖，一条命令启动，适合答辩现场 |
| 云端正式 | PostgreSQL 13+ | 腾讯云 TDSQL-C / 阿里云 RDS / Supabase 均可 |
| 接入方式 | 环境变量切换驱动 | `DB_DRIVER=sqlite \| pg` + `DATABASE_URL`，代码共用一套 SQL |
| 对象存储 | 腾讯云 COS / 阿里云 OSS | 学生卡照片与 AI 源图正式版存储（PRD Q1 关闭项）|

## 2. ER 关系

```text
users 1 ─ N event_staff N ─ 1 events 1 ─ N registrations 1 ─ N files
                                  1 ─ N event_groups
                                  1 ─ N matches 1 ─ N match_goals
                                               1 ─ N match_subs
                                               1 ─ N match_cards
每个写操作 → audit_log
积分榜 / 射手榜 = 派生数据，由已完赛比赛实时计算，不落库
```

## 3. 核心表

| 表 | 用途 | 关键字段 |
|---|---|---|
| `users` | 账号与角色 | phone（唯一）、role、emp_id、status |
| `events` | 赛事 | name、season、status（pending/signup/live/ended）|
| `event_staff` | 赛事级授权 | event_id、user_id、event_role |
| `registrations` | 球队报名主档 | team_name、status、reviewed_by、created_by |
| `registration_members` | 球员名单 | name、phone、is_contact（逐人学生卡文件关联 files）|
| `files` | 材料/文件元数据 | owner_type、owner_id、kind、path |
| `event_groups` | 抽签分组 | group_name、registration_id |
| `matches` | 比赛主档 | team_a/b、date、referee、score、status、lineup_a/b（首发/替补 JSON）|
| `match_goals/subs/cards` | 比赛明细 | 球员、时间、牌型/换人（驱动时间轴渲染）|
| `audit_log` | 审计 | user、action、entity、ip、detail |

## 4. 上线执行步骤（以腾讯云为例）

1. 创建 PostgreSQL 实例（TDSQL-C 或 RDS），白名单放行后端服务器。
2. 执行正式 DDL：

   ```bash
   psql "$DATABASE_URL" -f database/schema.sql
   ```

3. 后端环境变量：

   ```bash
   DB_DRIVER=pg
   DATABASE_URL=postgres://user:pass@host:5432/greensinbit
   JWT_SECRET=<64位随机串>
   ```

4. 前端静态资源可放 COS/OSS + CDN；后端只提供 `/api/*`，通过 `CORS_ORIGIN` 限制来源。
5. 开启 RLS（schema 已含示例）与备份策略（每日自动备份、7 天恢复）。

## 5. 一致性设计

- 所有业务写入在服务端完成，榜单不落库，从根上消除“改了结果忘同步榜单”的问题。
- 删除赛事/比赛依赖外键 `ON DELETE CASCADE`，材料文件先清理物理文件再删记录。
- SQL 全部使用位置参数，输入统一按文本渲染，避免 SQL 注入与 XSS。
- 单机演示无事务压力；生产环境建议把“录入结果”整理为单条事务（代码已按事务编写，SQLite/PG 通用）。

## 6. 数据安全

- 密码使用 `scrypt` 加盐哈希，绝不落明文；
- JWT 12 小时过期，密钥通过环境变量注入；
- 学生卡照片按文件级权限读取（见权限设计文档）；
- 建议正式版对手机号/学号字段做加密或脱敏存储。
