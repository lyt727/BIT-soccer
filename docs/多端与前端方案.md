# 绿茵BIT · 多端（Android / iOS / 鸿蒙）与前端方案

## 1. 本次交付形态

本次前端为**移动端优先的响应式 Web App（PWA）**：

- 手机浏览器（Android Chrome / iOS Safari / 鸿蒙浏览器）直接访问同一地址即可使用；
- 已配置 `manifest.webmanifest` 与图标，安卓/鸿蒙可“添加到主屏幕”作为独立应用运行；
- 同一局域网内手机访问 `http://<电脑IP>:3000` 可现场演示；
- 单代码库覆盖三种系统浏览器，无应用市场上架成本，适合产品 Demo 与校招答辩。

## 2. 为什么这样设计（面试表述）

产品迭代遵循“**先验证业务闭环，再考虑分发**”：

1. PRD 的核心痛点是报名/分组/赛程/榜单的流程一致性，先用 Web 端跑通全流程与权限；
2. 移动端体验按 480px 宽度设计与验收（PRD 非功能要求）；
3. 界面按“手机 App 习惯”设计：顶部导航、底部主入口、全屏弹层表单、卡片式列表，可直接作为后续原生 App 的视觉稿。

## 3. 三种原生化路线（正式版选型）

| 方案 | Android | iOS | HarmonyOS NEXT | 推荐度 |
|---|---|---|---|---|
| uni-app（Vue3）| ✅ 原生 APK | ✅ IPA | ✅ 鸿蒙（HBuilderX 编译）| 推荐：一套代码三端，生态最贴近国内校园 |
| React Native | ✅ | ✅ | 社区方案（RNOH）| 工程团队为 RN 时可选 |
| Flutter | ✅ | ✅ | OpenHarmony 社区分支 | 需评估鸿蒙官方支持节奏 |
| 自研三套 | ✅ | ✅ | ✅ | 不推荐：三倍维护成本，校园产品无必要 |

**建议路线**：先用本仓库前端页面作为交互基准 → 用 uni-app 重写页面（组件级迁移，接口不变）→ HBuilderX 云打包三端安装包。

## 4. 接口天然支持多端

- REST + JSON + JWT，客户端只需保存 Token；
- 角色权限由服务端返回的 `permissions` 决定，原生端同样只展示有权限的入口；
- 上传接口接受 base64，便于 Web/原生统一；原生端也可改为直传对象存储后提交 URL。

## 5. PWA 说明

- `manifest.webmanifest`：应用名/图标/独立窗口；
- iOS Safari 需要用户“分享 → 添加到主屏幕”；
- 鸿蒙/安卓浏览器一般可直接安装；
- 生产环境建议升级 HTTPS，PWA 全能力（离线、推送）需要安全上下文。
