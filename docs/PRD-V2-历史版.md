# 绿茵BIT · 校园足球赛事管理系统 PRD

**一句话**：把校园足球赛从报名到完赛的管理收进一个系统，管理员不再抄数、榜单不出错；核心是 **AI 识图把裁判报告读成结构化数据，人只负责复核**。

## 1. 背景与目标

**现状**：校内办赛靠 Excel、微信群、足球中国 APP，痛点在三个环节：

- **报名乱**：谁报没报、材料齐不齐，信息散在聊天里，靠人工催、易漏；
- **数据靠人同步**：分组、赛程、积分榜、射手榜分开维护，改了这处忘了那处，错了难发现；
- **录分慢**：进球、换人、红黄牌要从裁判纸上逐项敲，榜单还要手工算——每场 15–30 分钟，榜单常滞后 2–3 天。

**目标**：让"录比赛结果"成为唯一的人工环节，其余全部由系统算。

| 指标 | 口径 | 目标 |
|---|---|---|
| 报名审核耗时 | 提交 → 审完 | ≤ 1 个工作日 |
| 榜单准确率 | 与已录入结果一致 | 100%（系统算） |
| AI 识别有效率 | 识别后人工直接采用的比例 | ≥ 80% |
| 录入耗时 / 场 | 结果录入到榜单更新 | 人工 < 5 分钟；AI < 2 分钟 |

**为什么选 AI 切入**：录分是最耗时、最易错的环节，而多模态模型已能把"看整张报告 → 结构化 JSON"合成一步，几周可做出"机器读 + 人复核"的 MVP。可靠性不依赖"模型永远对"，而靠流程兜底（见 §4.5）。选型与成本详见 [AI产品决策说明](docs/AI产品决策说明.md)。

## 2. 用户与权限

### 2.1 角色
系统三种角色，权限为包含关系：**参赛球员 ⊆ 数据录入员 ⊆ 管理员**。

| 角色 | 是谁 | 做什么 |
|---|---|---|
| 管理员 | 校足协 | 建赛事、审报名、抽签、排赛程、指派录入员、修订结果、查日志 |
| 数据录入员 | 被指派的同学 | 在**被指派的赛事**内录结果、复核 AI 识图 |
| 参赛球员 | 各队领队/队长/队员 | 整队报名（含学生卡）、看自己球队和榜单 |

> 队内角色（主教练/领队/队长/队员）只是球队内分工，与系统角色无关。

### 2.2 两级授权
① 全局角色决定"能做哪类事"；② 赛事级指派（`event_staff`）决定录入员"能操作哪届赛事"。管理员默认全部赛事。关键写操作留操作日志（谁、何时、做了什么）；云端数据库再用 PostgreSQL RLS 行级权限兜底（详见 [权限设计说明](docs/权限设计说明.md)、[云数据库方案](docs/云数据库方案.md)）。

### 2.3 能力矩阵

| 能力 | 管理员 | 录入员 | 球员 |
|---|---|---|---|
| 看赛事 / 赛程 / 榜单 | ✅ | ✅ | ✅ |
| 建删赛事、流转状态 | ✅ | — | — |
| 审报名、看学生卡 | ✅ | — | — |
| 抽签 / 排赛程 / 删比赛 | ✅ | — | — |
| 录结果、AI 识图 | ✅ | ✅（被指派赛事） | — |
| 整队报名 / 加队 / "我的球队" | ✅ | ✅ | ✅ |
| 操作日志 | ✅ | — | — |

## 3. 核心流程与名词

### 3.1 主流程

建赛事 → 报名（整队 + 每人学生卡）→ 逐队审核 → 截止名单锁定 → 抽签分组 → 排赛程 → 每轮录结果（人工 / AI 识图）→ 榜单自动更新 → 全部完赛，赛事结束。

两个分支：队员可加入别人已建好的队；报名截止后名单锁定不可再改。

### 3.2 名词速查

| 术语 | 说明 |
|---|---|
| 赛事 | 一届比赛，状态：报名中 → 进行中（可排赛、录分）→ 已结束（结果锁定） |
| 比赛 / 场次 | 单场对阵，状态仅"未开赛 / 已完赛" |
| 球队报名 | 整队报名形成的参赛单位，含名单与每人学生卡；名单锁定于赛事进入"进行中" |
| 报名联系人 | 名单第一人，须为发起报名者本人 |
| 裁判报告 | 赛后纸质记录，AI 识图的输入物 |
| 榜单 | 积分榜 / 射手榜，纯派生数据、系统算、不可手改 |
| 演示 / 真实模式 | 未配模型密钥走演示流程；配置后切真实视觉模型（见 §4.5） |

## 4. 功能需求

> 各功能均已实现。演示账号见 [权限设计说明](docs/权限设计说明.md)。

### 4.1 赛事与首页
- 首页展示"进行中"赛事横幅（球队数、已完成/总场次、小组数），下方为全部赛事卡片。
- 有权限者可建赛事（名称、赛季、说明）或删除（二次确认，提示将连带删除报名/分组/赛程/统计）；赛事名重复前端拦截。

### 4.2 账号与报名
- 登录：手机号 + 验证码，无密码；新手机号即注册，默认为参赛球员。
- **整队报名**：球队名、球衣三色、队员名单（≥2 人）。每人填姓名、手机号、队内角色、球衣号（队长/队员必填）、学生卡照片；名单第一人为联系人且必须是报名者本人。
- 管理员在"待审核"逐队通过/拒绝（可附原因）；与已通过球队**重名不能通过**。
- **名单锁定**：赛事进入"进行中"后，服务端拒绝新增/修改报名（`REG_LOCKED`），从数据层保证名单不可变。
- 队员可取消自己的报名（仅移除本人）；联系人是唯一时球队解散，否则联系人自动转给最早入队者。
- 一人同一赛事只能在一支球队，可加入别人已建好的队；"我的球队"聚合本人所有队伍。

### 4.3 抽签与赛程
- **抽签**：把全部已通过球队随机均衡分入若干组（组数可选 2/3/4/6，≤ 球队数），组间球队数差 ≤ 1；重新抽签覆盖旧结果（有提示）。
- **排赛程**：管理员添加比赛——选主客队，填时间/场地/裁判组（主裁、两个助理裁判、第四官员）；首发替补与比赛服色可不填，不影响开赛。
- **编辑分流**：未开赛 → 编辑赛程信息；已完赛 → 打开结果表单并**预填当前数据**，保存即修订（覆盖原比分/进球/换人/红黄牌并重算榜单，界面明示"将覆盖原有记录"）。删除比赛同理。
- 特殊情况说明（延期/中断/申诉等）：管理员与被指派录入员可写，队员只读。

### 4.4 结果录入与榜单
一套表单同时服务"录入"与"修订"：入口选未开赛的比赛=首次产生结果，已完赛=预填覆盖并重算榜单，走同一保存接口。仅当**赛事已结束**时结果锁定、拒绝修改。

录入内容：比分、每粒进球（人/号码/时间/是否点球）、换人、红黄牌、首发替补与比赛服色、裁判组。

**进球与比分解耦**：进球为可自由增删的行（"＋添加"逐条录），行数不必等于比分，比分与进球哪个先改都行、互不锁死；记不清的进球留空即"未登记"，不阻塞录入。

规则：
- 填了姓名/号码的球员必须在双方**已报名名单内**找到（防止拿别队的人凑数；名单进行中即锁定），记不清就留空；
- 提交即触发积分榜、射手榜**重算**：积分胜 3 / 平 1 / 负 0，同分先比净胜球再比进球数；射手榜按进球降序、点球少者列前。榜单为派生数据，无手工入口；
- 已完赛比赛详情可看技术统计与时间轴（进球/红黄牌/换人按时间）。

校验拦截：比分须非负整数；换人须同时填上/下场球员；红黄牌缺球员或牌型非法即拦截。

### 4.5 AI 识图（核心 AI 功能）
目标：把最耗时的人工录分压缩成"**拍照 → 机器读 → 人复核 → 一键入库**"。

- 入口：录分页 / 赛程页，需 `result.record` 权限且在赛事工作人员内、赛事未结束。
- 输入：JPG/PNG，**一次最多 2 张**（第 3 张起前端拦截；多图互补不冗余），单张 ≤ 12MB、上传前压缩到 1600px。
- 输出：双方名单、比赛服颜色、比分、进球、换人、红黄牌、裁判组 → 填进结果表单。

**可靠性 = 流程，不赌"模型永远对"**：
1. 识别结果先给人看，**逐项可改**；
2. 单字段置信度 < 0.75 → 界面**标红**，强制人工确认后才可提交；
3. 整体置信度 < 0.4 或校验不过 → 判"识别失败"，引导改人工录入，**不产生半成品数据**；
4. 点提交前不写任何库，提交后才更新比赛与榜单；每次识别留日志（操作人/图片数/模型/赛事）；
5. 模型"编造"名单外球员 → 候选名单约束 + 服务端名单硬校验双重拦截。

> **现状说明（如实）**：已接通用视觉模型（qwen3-vl-plus / qwen-vl-max / GLM-4V 等可切换）。本地无模型密钥时走**演示模式**（按真实名单生成示例数据走通流程，界面标明"演示"）；真实识别准确率尚未评测，评测方案见 [AI产品决策说明](docs/AI产品决策说明.md#5-效果评测指标已定义数据待产出)。

### 4.6 赛事详情页
顶部赛事信息，下方标签切换：报名管理 / 抽签分组 / 赛程安排 / 数据统计；各角色看到的标签与操作随权限收敛。

## 5. 非功能与安全

| 项 | 要求 |
|---|---|
| 多端 | 手机浏览器为主（PWA 即用），桌面可用；可打包 App（见 [多端与前端方案](docs/多端与前端方案.md)） |
| 权限与审计 | RBAC + 赛事级指派，关键写操作留日志；云端数据库加 RLS 行级权限兜底 |
| 上传 | 只收 JPG/PNG，单张 ≤ 12MB、一次 ≤ 2 张，前端先压缩 |
| 验证码（生产） | 接云短信后服务端限频：60 秒/次、5 次校验上限、5 分钟过期 |
| 数据一致性 | 榜单/统计为派生数据实时重算；名单锁定由服务端在数据层保证 |
| 兼容 | Chrome / Edge / Safari 最近两个大版本 |

## 8. 验收标准

- **管理员**：建赛事 → 审报名 → 抽签 → 排赛程 → 指派录入员 → 对已完赛比赛"编辑"修订结果，榜单随之更新。
- **球员**：注册 → 整队报名传学生卡 → 截止后名单锁 → 取消报名 / 加入已建好的队。
- **录入员**：人工录一场（进球"＋添加"逐条录，比分与进球可独立修改）；再走 AI 识图录一场（2 张上限、低置信标红复核、失败转人工、不落脏数据），榜单正确。
- **接口冒烟**：`node scripts/smoke-test.mjs` 全绿（29 项）。
