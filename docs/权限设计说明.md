# 绿茵BIT · 权限与账号设计说明（V2）

## 1. 账号体系

- 登录/注册统一使用 **手机号 + 姓名 + 密码**，不需要短信资质即可上线；
- 密码 6–64 位，服务端用 scrypt 加盐散列存储（Cloudflare 版为 PBKDF2-SHA256 / 10 万轮），接口从不返回散列；
- 账号不存在与密码错误返回同一句提示，避免暴露手机号是否已注册；登录失败写审计日志（含来源 IP）；
- 未注册手机号可在线注册，注册后自动成为“参赛球员”；
- 管理员在“成员管理”中可创建/停用账号、调整角色、重置成员密码（重置后旧密码立即失效）；
- 短信验证码通道（腾讯云 / 阿里云 / webhook）作为**备选登录方式**保留：配置后可用「验证码登录」，并给注册流程加回手机号校验。演示验证码默认只在非生产环境回显。

## 2. 角色矩阵

| 能力 | 管理员 | 数据录入员 | 参赛球员 |
|---|---|---|---|
| 查看赛事/赛程/榜单 | ✅ | ✅ | ✅ |
| 创建/删除赛事、状态流转 | ✅ | - | - |
| 用户与成员管理 | ✅ | - | - |
| 整队报名 / 加入球队 | ✅ | ✅ | ✅ |
| 审核报名 / 查看学生卡 | ✅ | - | - |
| 抽签分组 | ✅ | - | - |
| 添加/编辑/删除比赛 | ✅ | - | - |
| 录入比赛结果 | ✅ | ✅（被指派赛事） | - |
| AI 识图 | ✅ | ✅（被指派赛事） | - |
| 操作日志 | ✅ | - | - |

说明：管理员合并了原“超级管理员 + 赛事管理员”；不再单设队长角色，报名由任意“参赛球员”作为报名联系人发起整队名单。

权限为包含关系：**参赛队员 ⊆ 数据录入员 ⊆ 管理员**。参赛队员拥有的能力（报名、查赛程、查榜单），数据录入员全部拥有，并额外拥有录分与 AI 识图；管理员在数据录入员基础上拥有全部管理能力。

## 3. 两级授权

1. 全局角色决定“能做哪类事”；
2. `event_staff` 决定数据录入员能操作哪届赛事；管理员天然拥有全部赛事权限；
3. 报名材料按“管理员 / 上传者本人 / 名单内本人手机号”放行。

## 4. 报名锁定

- 赛事处于 `signup` 时开放报名；
- 报名中，球队可随时编辑整队名单（姓名/手机号/学生卡照片），编辑需要重新上传照片；
- 管理员可任意切换赛事状态（待开始 / 报名中 / 进行中 / 已结束，不做单向限制）；
- 状态切到 `live`（进行中）后，服务端拒绝新增/修改报名（`REG_LOCKED`），从数据层保证“报名结束后名单不可变”。

## 5. 云库 RLS 兜底

`database/schema.sql` 已提供 PostgreSQL RLS 示例：登录用户可读赛事；写操作仅 `admin` 角色放行；报名数据按创建人/管理员范围读取。

> 需要让成员自助升级时，应只开放“数据录入员”角色的申请 + 管理员审核。
