# 绿茵BIT · 校园足球赛事管理系统 PRD（V3.0 精简版）

**一句话**：把校园足球赛从报名到完赛收进一个系统；核心是 **AI 识图把裁判报告读成结构化数据，人只负责复核**，榜单和统计全部由系统自动计算。

| 文档信息 | 内容 |
|---|---|
| 版本 / 日期 | V3.0 · 2026-09-22 |
| 状态 | 已实现，可运行演示 |
| 一句话价值 | 报名不乱、数据不抄、榜单不出错 |

---

## 1. 目标

**现状痛点**

- 报名散在群聊和表格里：谁报了、材料齐没齐，靠人工催和核对。
- 分组、赛程、积分榜、射手榜分开维护：改一处忘一处，错误难追溯。
- 录分靠手工：进球、换人、红黄牌逐条敲，一场 15–30 分钟，榜单滞后数天。

**目标**：把“录比赛结果”变成唯一的人工环节，其余由系统自动完成。

| 指标 | 口径 | 目标 |
|---|---|---|
| 报名审核耗时 | 提交 → 审核完成 | ≤ 1 个工作日 |
| 榜单准确率 | 与已录入结果一致 | 100%（系统计算） |
| AI 识图有效率 | 识别后人工直接采用的比例 | ≥ 80% |
| 单场录分耗时 | 结果录入 → 榜单更新 | 人工 < 5 分钟；AI < 2 分钟 |

## 2. 用户与权限

**系统角色（权限为包含关系：参赛球员 ⊆ 数据录入员 ⊆ 管理员）**

| 角色 | 是谁 | 核心权限 |
|---|---|---|
| 管理员 | 校足协 | 建/删赛事、切换状态、审核报名、抽签、排赛程、指派工作人员、修订结果、查看日志 |
| 数据录入员 | 被指派的同学 | 在被指派赛事内：录结果、AI 识图、编辑淘汰赛场次、填写特殊情况与比赛工作人员 |
| 参赛球员 | 各队成员 | 报名/加入球队、完善本人信息、查看赛程与榜单 |

> 队内角色（主教练 / 领队 / 队长 / 队员）是球队内部分工，不等于系统角色。

**两级授权**：全局角色决定“能做哪类事”，赛事指派（`event_staff`）决定“能管哪届赛事”；关键写操作全部记录审计日志，云数据库用 RLS 兜底。

**能力矩阵**

| 能力 | 管理员 | 数据录入员 | 参赛球员 |
|---|---|---|---|
| 查看赛事 / 赛程 / 榜单 | ✅ | ✅ | ✅ |
| 建删赛事、切换状态、编辑赛事信息 | ✅ | — | — |
| 审核报名、查看完整报名信息 | ✅ | ✅（只读） | ✅（只读） |
| 抽签分组、编辑小组赛 | ✅ | — | — |
| 新增/编辑/删除淘汰赛 | ✅ | ✅（被指派赛事） | — |
| 录结果、AI 识图、特殊情况、比赛工作人员 | ✅ | ✅（被指派赛事） | — |
| 报名 / 加入球队 / 取消报名 | ✅ | ✅ | ✅ |
| 操作日志 | ✅ | — | — |

## 3. 核心流程

`建赛事（选赛制）→ 报名/加入球队 → 审核 → 报名截止锁定 → 抽签（分组或编排赛程）→ 排比赛 → 录结果（人工/AI）→ 榜单与人员统计自动更新 → 导出`

**赛事状态**：待开始 / 报名中 / 进行中 / 已结束。管理员可任意切换；报名中可编辑名单，切换到进行中后名单与报名锁定。

**演示数据规模**：15 支球队、A/B/C/D 四组（4/4/4/3）、每队 15 人；21 场小组赛 + 半决赛/决赛等淘汰赛。

## 4. 功能需求

### 4.1 账号与登录
- 手机号 + 姓名 + 密码登录注册，新账号默认角色为参赛球员；密码用 scrypt 加盐散列存储（Cloudflare 版 PBKDF2-SHA256），任何接口都不返回散列。
- 账号不存在与密码错误返回同一句提示，避免暴露手机号是否已注册；登录失败写审计日志（含来源 IP）。
- 短信验证码登录作为备选通道保留：配置腾讯云 / 阿里云短信后可用，服务端限频（60 秒/次、5 次校验、5 分钟过期）；演示验证码默认只在非生产环境回显。
- 管理员可在“成员”页创建账号（可指定或自动生成初始密码）、调整角色、停用账号、重置成员密码。

### 4.2 赛事管理
- 首页展示进行中赛事横幅 + 全部赛事卡片（球队数、已完成/总场次、小组数、状态）。
- 管理员可创建赛事、编辑赛事名称与介绍、删除赛事（二次确认，级联删除报名/分组/赛程/统计）。
- 赛事状态四种，管理员可任意切换；不同状态用不同颜色标识，非管理员只读。

### 4.3 球队报名
- 任意角色都可以**创建球队**或**加入已有球队**；同一人在同一赛事只能报一支队（互斥），可随时取消本人报名。
- 每队必须上报：**球衣上衣、短裤、球袜三种颜色**；每名成员上报姓名、手机号、学生卡照片、队内角色、球衣号码。
- 队内角色：主教练 / 领队 / 队长 / 队员，可一人多职；**每队只能有一名主教练、一名队长**。
- 队长与队员必须有球衣号码，**同队号码不能重复**；号码不要求连续，名单按号码升序排列。
- 报名期间可编辑整队名单或完善本人信息；赛事进入“进行中”后服务端锁定（`REG_LOCKED`）。
- 报名列表展示球衣三色、主教练、领队；点“详细名单”可查看全员号码、手机号和学生卡。
- 管理员拥有审核权限：通过 / 拒绝（可填原因）；与已通过球队重名不能通过。

### 4.4 抽签分组
- 管理员把已通过球队随机均衡分组，组数可选 2/3/4/6；组间球队数差 ≤ 1。
- 重新抽签覆盖旧结果，界面提前提示。

### 4.5 赛程安排
- **赛制三选一**（创建赛事时选定，已有赛程后不可修改）：
  - **单循环联赛**：每两队交手一次，抽签时按轮转法生成全部对阵并分配到各轮；积分榜为一张总表。
  - **小组赛 + 淘汰赛**：小组赛（A–F 组）+ 单回合淘汰赛。
  - **纯淘汰赛**：对阵全部手动添加，不产生积分榜。
- **淘汰赛轮次**：1/8 决赛、1/4 决赛、半决赛、三四名决赛、决赛，也可自定义名称（≤20 字）。
- 权限：小组赛仅管理员可增删改；淘汰赛由管理员或数据录入员添加并选择轮次。
- **必填项只有：比赛阶段、轮次（小组或淘汰赛轮次）、主客队**；日期、时间、场地、裁判组、名单、球衣颜色、备注均为选填。
- 裁判组固定四人：主裁判、第一助理、第二助理、第四官员。
- 每场比赛提供“特殊情况说明”（延期/中断/申诉等），管理员与数据录入员可编辑，参赛球员只读。
- 每场比赛的 AI 识图入口与技术统计入口并列。

### 4.6 比赛技术统计
每场比赛详情包含：

- 双方首发 / 替补名单（号码 + 姓名）、比赛服颜色；
- 竖版时间轴：进球、换人、红黄牌（球员/号码 + 时间）；
- 裁判组（四人）；
- 比赛工作人员：比赛监督、拍照、录像、解说、战报（可手动填写姓名）。

### 4.7 结果录入与 AI 识图
- 录入内容：比分、进球（球员/号码/时间/是否点球）、换人、红黄牌、裁判组、首发替补、球衣颜色。
- 进球名单行数必须与比分一致，每球一行，允许留空记为“未登记”。
- 提交后自动重算积分榜、射手榜；只有赛事“已结束”才锁定结果。
- **AI 识图**：上传裁判报告照片（JPG/PNG，最多 6 张，单张 ≤ 12MB，前端压缩到 1600px），一次识别输出双方名单（号码+姓名）、球衣颜色、比分、进球、换人、红黄牌、裁判组。
- 识别结果逐项可改；字段置信度 < 0.75 标红强制复核；整体置信度 < 0.4 或校验失败则提示改用人工，不写入脏数据。
- 复核后一键填入并提交，榜单自动更新；每次识别写审计日志。
- 支持演示模式（无需密钥）与真实视觉模型（qwen-vl-max / gpt-4o 等，配 Key 切换）。

### 4.8 数据统计
- **小组赛积分榜按 A/B/C/D 组分别排名**：胜 3 平 1 负 0，同分依次比较净胜球、进球数。
- **射手榜**：全赛事汇总，按进球数降序，同进球数点球少者列前。
- **淘汰赛赛果**：按轮次展示对阵与比分。

### 4.9 人员统计
- 裁判组统计：主裁判、第一助理、第二助理、第四官员；
- 其他工作人员统计：比赛监督、拍照、录像、解说、战报；
- 每张表包含角色、姓名、工作场次，按场次从多到少排序。

### 4.10 导出到 Excel
- 赛程安排：一次性导出该赛事全部比赛，包含主客队名称、比分、阶段、组别、淘汰赛轮次等；
- 数据统计：小组积分榜（每组）、射手榜、淘汰赛赛果分别可导出；
- 人员统计：裁判组、其他工作人员分别可导出；
- 导出格式 `.xls`，Excel / WPS 可直接打开。

## 5. 数据模型（核心）

| 实体 | 关键字段 |
|---|---|
| users | phone、name、role、status |
| events | name、season、description、status |
| event_staff | event_id、user_id、event_role（赛事级授权） |
| registrations | team_name、球衣三色、status、created_by |
| registration_members | name、phone、roles、jersey_no、is_contact |
| files | 学生卡照片（文件级权限） |
| event_groups | 小组与球队 |
| matches | 阶段、组别、淘汰赛轮次、主客队、比分、裁判组、工作人员、特殊情况、名单 |
| match_goals / subs / cards | 进球、换人、红黄牌明细 |
| audit_log | 关键操作留痕 |

积分榜、射手榜为派生数据，实时计算，不单独存储，保证与比赛结果一致。

## 6. 非功能要求

| 项 | 要求 |
|---|---|
| 多端 | 手机浏览器优先（PWA 可直接使用），桌面可用 |
| 权限与安全 | RBAC + 赛事级指派 + 文件级校验 + 审计日志；生产加 RLS |
| 数据一致性 | 榜单/统计实时重算；名单在服务端锁定 |
| 上传限制 | 仅 JPG/PNG，单张 ≤ 12MB，AI 上传最多 6 张 |
| 密码安全 | scrypt 加盐散列（Cloudflare 版 PBKDF2-SHA256 / 10 万轮）；接口不回传散列；重置密码立即失效旧密码 |
| 验证码安全 | 60 秒限频、5 次校验上限、5 分钟过期；演示验证码生产环境默认关闭 |
| 部署 | Node.js 零依赖本地运行；提供 Docker / Compose / HTTPS 配置；可接云数据库 |
