# 绿茵BIT · AI 识图产品决策说明（产品经理视角）

> 本文以「AI 产品经理」的口径，讲清一个核心 AI 能力的**需求论证 → 方案选型 → 可靠性设计 → 评测与成本 → 演进路线**。
> 与 [docs/AI识图技术方案.md](AI识图技术方案.md) 互为补充：那份偏实现，这份偏**决策过程与取舍**，供面试讲「为什么这样做」。

## 1. 场景与用户问题（需求侧，为什么值得做）

**场景**：校园足球联赛每轮十余场。赛后裁判提交**纸质裁判报告**（打印表格 + 手写填字），记录双方首发/替补（号码+姓名）、比赛服颜色、比分、进球（球员/号码/时间/点球）、换人、红黄牌、裁判组名单。

**现状痛点**（无 AI 时）：
- 录入人员需把整张报告逐字段敲进系统 → **每场约 15–30 分钟**（打印版可复制粘贴，手写版更慢），量大易错；
- 榜单（积分/射手）依赖录入完成后人工核对，**榜单往往滞后一天**，赛事期间的「即时战报」价值被浪费；
- 手写号码/姓名错一个，射手榜与停赛统计就错，**溯源困难**。

**用户诉求**：录得快、别录错、榜单及时更新。

**「为什么是现在」**：多模态大模型把「看整张表 → 语义理解 → 结构化输出」合成一步完成，且能直接输出与系统字段一一对应的 JSON；三年前需要 OCR + 规则引擎 + 大量模板，而现在一个 OpenAI 兼容接口即可在几周内做出可复核的 MVP。这是**技术可行性的拐点**带来的产品机会。

## 2. 方案空间对比（为什么选视觉大模型，而非纯 OCR）

| 方案 | 能看图片 | 字段结构化 | 抗格式/手写差异 | 幻觉/错字控制 | 人工复核成本 | 结论 |
|---|---|---|---|---|---|---|
| A. 纯人工录入 | — | 手工 | — | 靠人 | 每场 15–30 min | 基线，仅作对照 |
| B. 通用 OCR（腾讯/阿里/Paddle） | ✅ | ❌ 只有文字流 | 中 | 高（需二次校对） | 仍需人工拼字段 | 解决一半，性价比低 |
| C. 模板/规则匹配 | ❌ | 依赖固定模板 | 低 | — | 每新格式重做 | 校园报告格式不统一，不可维护 |
| **D. 视觉大模型结构化输出** | ✅ | ✅ 一次出全字段 JSON | 高 | 可控（见 §4） | **<1 分钟复核** | **MVP 采用** |
| E. OCR 出候选文本 + LLM 只做结构化 | ✅ | ✅ | 高 | 更高（先约束输入） | <1 分钟 | **正式版升级目标** |

**决策**：MVP 用 **D**（直连视觉大模型 + 人在回路兜底），因为它是「代码量最小、最快验证产品价值」的路径；把 **E** 留给正式版做准确率与成本的优化，而不是一开始就背上 OCR 管线复杂度。

## 3. 模型选型决策（含国产合规考量）

代码采用 **Provider 抽象**（`server/src/services/aiRecognition.js`），任何 **OpenAI 兼容协议**的视觉模型只需改 3 个环境变量即可切换 → **选型成本极低，是刻意做的架构决策**（面试可强调「选型不被绑定」）。

| 模型 | 中文手写/印刷理解 | 结构化输出 | 价格量级* | 数据合规/境内可用 | 免费额度 | 备注 |
|---|---|---|---|---|---|---|
| 阿里云百炼 `qwen3-vl-plus` | 好（新一代 VL，OCR/文档结构化更强） | ✅ | 低 | ✅ 数据留在境内 | ✅ | **当前演示首选**；默认 base URL 已内置；`AI_VISION_THINKING=off` 保证结构化 JSON |
| 阿里云百炼 `qwen-vl-max` | 好（中文语料强） | ✅ | 更低 | ✅ | ✅ | 作为评测基线对照（换 env 即可回退） |
| 智谱 `GLM-4V` | 好 | ✅ | 低 | ✅ | ✅ | 国产自主，北京大厂叙事友好 |
| OpenAI `gpt-4o` | 良（中文略逊 VL 系） | ✅ | 中 | ⚠️ 出境 | ❌ 需境外支付 | 用于能力基准对比 |
| MiniMax `abab` 系列 | 良 | ✅ | 低 | ✅ | ✅ | 备选 |

\* 具体以官方定价页为准。本场景单次识别图片少、输出上限 2200 token，**学生用量（数十张）费用几乎可忽略**；故「价格」不是当前约束，**合规与中文效果**才是。

**决策逻辑**：面向「北京互联网大厂 AI 产品岗」答辩与后续可上线性，默认推荐**国产 + 境内部署**（百炼/智谱）；保留 OpenAI 通道仅作评测对照。生产切换成本 ≈ 改 env，故此项决策**不阻塞、可后置**，符合「先验证价值，再定厂商」的 PM 节奏。

## 4. 幻觉与可靠性设计（「AI 出错怎么办」的答案）

面试必问「模型胡说怎么办」。本项目的答案不是「模型不会错」，而是**把可靠性建在流程与约束上**（全部已实现 ✅）：

1. **结构化强约束**：System Prompt 内置 JSON Schema，`temperature=0`，要求「图上没有就不写、看不清就给空值并降置信度」；
2. **候选名单注入**：把本场候选球队名单传给模型，只允许同音/简写纠错、**禁止联想补全**——从源头压掉「编造一个队/球员」；
3. **服务端二次校验**（不只信模型）：比分非负整数、进球数与比分一致、牌型枚举、号码姓名成对、双方能在候选球队中定位；不满足即判失败，**宁可不写、不写错**；
4. **多图互补**：记分表 + 比分照片可一起上传，逐图阅读再合并；
5. **人在回路（Human-in-the-loop）兜底**：
   - 整体置信度 < 0.4 → 直接判「识别失败，请改用人工录入」，**不落任何脏数据**；
   - 字段置信度 < 0.75 → 前端**标红强制人工修改**后才能提交；
   - 未点「提交结果」前**不写任何库表**；落库才触发积分榜/射手榜重算；
   - 每次识别写入 `audit_log`（操作人/图片数/Provider/赛事），可回溯。

> 一句话结论：**产品靠「阈值 + 人工复核 + 审计」让 AI 的失败可控、可追溯、不产生脏数据**，而不是依赖模型「永远正确」。

## 5. 效果评测：指标已定义，数据待产出 🟡→📋

### 5.1 指标体系（已定 ✅）
- 主指标：**AI 识别有效率**（一次识别全字段可复核通过的比例）≥ 80%（对应 PRD 成功指标）；
- 字段级准确率：名单（姓名 exact + 同音模糊匹配）、号码、比分、时间轴事件（进球/换人/红黄牌）、裁判组、比赛服颜色 分别统计；
- 辅助：人工复核率、平均复核耗时、bad-case 占比。

### 5.2 评测方法（📋 待执行）
- 标注集：≥50 张（起步 20 张），来源 = 真实/自绘裁判报告照片，**覆盖打印、手写、倾斜、反光、多表合一、缺漏**等坏例；
- 每张人工标注 ground truth（可复用代码已有的 JSON Schema 做半自动标注模板）；
- 跑真实模型 → 算字段级 P/R/准确率 → **bad-case 归类**（手写/涂改/模糊/列表错位）→ 据此决定是否升级 OCR+LLM 混合（§2-E）。

### 5.3 现状边界
- 真实评测**未跑**（因未接模型）；demo Provider 仅验证**流程正确性**（上传→识别→预览→复核→落库→榜单重算），已由冒烟测试覆盖 ✅。

## 6. 接入真实模型：最小步骤（投递前建议执行一次）

在 `server/` 下创建/编辑 `.env`：

```bash
# 阿里云百炼（推荐，代码内置默认地址）
AI_VISION_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
AI_VISION_MODEL=qwen3-vl-plus
AI_VISION_API_KEY=sk-你的key
AI_VISION_THINKING=off   # qwen3 系思考开关：off/on/auto；off 保证结构化 JSON（默认，可不写）
# AI_PROVIDER=auto        # 留 auto 即可：有 key 自动走 vision，无 key 自动降级 demo
# 评测基线可临时把 MODEL 换回 qwen-vl-max / gpt-4o 对照（代码会为其他模型自动忽略 THINKING 参数）
```

重启服务后，页面 AI 入口徽标会从「模拟识别」变为 **「真实视觉模型：qwen-vl-max」**，上传真实裁判报告照片即可得到真实识别结果。代码判定逻辑：`aiProvider !== 'demo' && aiVisionApiKey 存在 → vision 模式`。

## 7. 成本与单位经济（口径估算，非实测）

> 以下为**量级估算口径**，用于讲「为什么这个 AI 功能养得起」，数值以正式压测为准。

- **单次识别成本**：≤6 张图 + 输出上限 2200 token，量级约几分钱级（VL 低档档位）；
- **人工 vs AI**：无 AI 约 15–30 分钟/场录入+核对；有 AI 约「拍照 + <1 分钟复核」/场（估算口径，请替换为你的实测）。工时节省即 ROI 来源；
- **规模想象**：单校一季 ≈ 上百场；产品可向 N 所高校复制。若向高校体育部门做轻 SaaS，单价可覆盖模型成本，单位经济为正。

## 9. 面试「三个为什么」速答

1. **为什么不用 OCR？** OCR 只给文字流，仍要人工拼字段、模板各异就废；视觉大模型一次给出与系统字段一一对应的结构化 JSON，且能报逐字段置信度。
2. **为什么允许 AI 犯错？** 因为可靠性来自**流程**而非「模型永远对」：阈值拒识 + 低置信标红强制复核 + 未确认不落库 + 审计留痕——把模型的不确定性关进产品规则的笼子里。
3. **为什么值得做？** 它把「一次性、线下、靠人的数据录入」变成「可复用、可评测、可规模化的数据管道」，足球只是第一个场景，能力本身可迁移。
